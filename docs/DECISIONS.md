# Журнал принятых решений

Здесь фиксируются решения, которые нельзя восстанавливать по памяти чата. Новое решение не удаляет старое: устаревшее помечается как superseded.

## D-001. Production — главный источник истины

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: фактическая конфигурация и поведение production выше локального Git и всех чатов. Перед документацией или новым deploy выполняется read-only сверка сервера.
- Причина: production собирался узкими deploy-скриптами и runtime-изменениями environment/БД; он не является Git checkout.

## D-002. Каждый платный фильм запускается с телефона

- Дата: 28–29 августа 2026.
- Статус: действует; заменяет эксперименты с прямым повторным запуском и lease-таймерами.
- Решение: покупка даёт право, но каждый конкретный фильм запускается только кнопкой «Смотреть» на телефоне. Прямой выбор оплаченного фильма в очках показывает просьбу нажать эту кнопку.
- Причина: попытки сделать автоматическое продолжение/переход между несколькими покупками привели к преждевременным блокировкам и более сложному автомату.

## D-003. Не возвращать дополнительный server-side таймер отсутствия

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: не использовать прежний 10-минутный presence timeout, `+30 секунд` grace разблокировки и автоматическую приостановку lease. Главный экран с «Начать просмотр» всегда должен разблокироваться; новый платный фильм затем запускается телефоном.
- Причина: сочетание нативного 60-секундного reset и дополнительных серверных таймеров вызывало циклическую блокировку и потерю запуска.

## D-004. Бесплатность — свойство ID очков

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: `VDNH/8`–`VDNH/50` бесплатны по `FREE_VIEWER_IDS`; `VDNH/1`–`VDNH/7` платны. Бесплатные очки запускают существующие фильмы напрямую без телефона и токена.
- Причина: льготный режим должен быть прозрачным и не зависеть от ежедневной ручной выдачи доступа.

## D-005. Offline гарнитуры — fail-open

- Дата: 29 августа 2026.
- Статус: действует как осознанный риск.
- Решение: если гарнитура полностью потеряла связь с control_server, не добавлять отдельные механизмы локальной блокировки; плеер может показать локальный каталог.
- Причина: пользователь выбрал «показывает всё, если нет связи». Надёжно enforce-ить оплату без связи текущий плеер не позволяет.

## D-006. Тестовые цены 1 ₽

- Дата: 28 августа 2026.
- Статус: временно действует.
- Решение: каждый фильм и каждый комплект стоят 1 ₽.
- Причина: развёртывание и пользовательские тесты оплаты.
- Откат: только отдельной задачей с применением сохранённого коммерческого профиля цен и проверкой корзины.

## D-007. Утренняя очистка с обязательным backup

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: ежедневно в 06:00 сначала делать SQLite backup с retention 14, затем деактивировать истёкшее/устаревшее состояние доступа.
- Причина: ночью реальных показов нет; нужна чистая операционная картина без потери аудита заказов.

## D-008. Один пароль для monitoring и site-admin

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: `/` и `/site-admin` используют общую подписанную Django session-cookie; секрет только в production environment.

## D-009. Нормализация числового ID

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: ведущие нули номера не создают новое устройство: `VDNH/02 == VDNH/2`.
- Причина: ранее статистика, доступ и WebSocket могли относить одно физическое устройство к разным идентификаторам.

## D-010. Автоматически назначать разные номера одинаковым конфигам не требуется

- Дата: 29 августа 2026.
- Статус: явно не задача.
- Решение: не разрабатывать auto-numbering конфигов гарнитур без нового прямого запроса.

## D-011. Банковский инцидент не был ошибкой cinema callback

- Дата: 25 августа 2026.
- Статус: закрыт.
- Решение: ошибка доступа между PayKeeper и банковским API-пользователем устраняется синхронизацией банковских реквизитов через PayKeeper/банк. Не менять callback/корзину без новых серверных доказательств.

## D-012. Секреты локально, но не в Git

- Дата: 29 августа 2026.
- Статус: действует.
- Решение: connection metadata и аварийные секреты хранятся в `.local-secrets/` с Windows ACL; ежедневный вход выполняется выделенным SSH-ключом. Git содержит только инструкции без значений.
