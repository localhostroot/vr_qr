# VR QR Cinema: обязательные правила работы

Этот файл применяется ко всему репозиторию. Перед работой с проектом сначала прочитайте:

1. `docs/CURRENT_STATE.md` — что сейчас фактически работает в production.
2. `docs/DECISIONS.md` — принятые продуктовые и технические решения.
3. Для размещения или диагностики production — `docs/RUNBOOK.md` и последние записи `docs/DEPLOYMENT_LOG.md`.
4. Для изменений просмотра/оплаты — `VIEWING_STATE_MACHINE.md`.
5. Для конфигурации гарнитур — `docs/VR_PLAYER_AND_HEADSET.md`.

## Иерархия источников истины

1. Фактические файлы, environment, БД, systemd и поведение работающего production.
2. Локальная рабочая копия, если она сверена с production по содержимому и тестам.
3. Документация, обновлённая после такой сверки.
4. Git-история и сообщения прошлых задач.
5. Обсуждения в чатах — только гипотезы и контекст; они не доказывают текущее состояние.

Если источники расходятся, не угадывайте. Сначала выполните read-only сверку production и явно зафиксируйте расхождение.

## Безопасность и секреты

- Не добавляйте пароли, токены, приватные ключи и production environment в Git, patch, журналы или ответы.
- Локальные секреты находятся в `.local-secrets/`, каталог обязан оставаться в `.gitignore`.
- Обычный вход на VM выполняется через SSH-алиас `vr-cinema-prod`; пароль допустим только как аварийный fallback.
- Не печатайте значения secret-файлов. Для проверки выводите только наличие, права и логический результат.
- Не изменяйте конфиги установленных плееров/гарнитур без отдельного прямого разрешения пользователя.

## Работа с production

- Диагностика не даёт разрешения на исправление. Начинайте с read-only проверок.
- Перед изменением определите точный список файлов/данных, резервную копию, health checks и способ rollback.
- Не копируйте на сервер всю рабочую директорию. Используйте узкий allow-list и подходящий `system_stuff/deploy-*.sh`.
- SQLite копируйте через SQLite backup/API Django-команды, а не обычным копированием активного файла.
- После размещения проверьте тесты, systemd, локальные порты, внешний HTTPS и ключевой пользовательский сценарий.
- После успешного production-изменения обновите `docs/CURRENT_STATE.md` и добавьте запись в `docs/DEPLOYMENT_LOG.md`.
- Одновременно production изменяет только одна задача/один оператор. Параллельные задачи готовят анализ и patch, но не размещают.

## Инварианты текущего продукта

- Для платных очков каждый фильм запускается отдельным нажатием «Смотреть» на телефоне.
- Для бесплатных очков прямой выбор фильма в гарнитуре разрешён по серверному списку устройств и не требует токена.
- Не возвращайте server-side таймер приостановки платёжного lease или grace после разблокировки без нового решения и полного сценарного теста.
- Не считайте `queue` доказательством оплаты; старые `addToQueue` и `fillQueue` остаются известным риском.
- Нормализуйте числовые ID: `VDNH/02` и `VDNH/2` — одно устройство.

## Проверки перед завершением

- Сверьте `git diff` и не включайте чужие/неотносящиеся изменения.
- Запустите проверки в объёме риска: Django tests, `node --test`, Svelte check/build.
- Отдельно перечислите непроверенное и не называйте его подтверждённым.
- Не пушьте документацию, которую пользователь ещё явно собирается редактировать, пока он не подтвердит финальную версию.
